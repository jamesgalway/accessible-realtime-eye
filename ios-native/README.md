# 实时慧眼 iPhone 原生版

## 2026-08-20 摄像头和麦克风按入口启动

- App 打开后先停在版本选择页，不预选绿云或阿里，也不创建实时慧眼网页。
- 在版本选择页，摄像头、麦克风和 LiDAR 都保持关闭；只有双击“打开绿云 Gemini 版”或“打开阿里百炼版”进入最终实时慧眼页面后才启动。
- 最终页面新增“返回入口选择”按钮。返回时先关闭闪光灯和原生相机，再停止网页中的所有音视频轨道并销毁网页会话。
- App 进入后台时原生相机和 LiDAR 继续按原规则停止；回到前台时，只有仍处于最终实时慧眼页面才允许重新启动相机。
- 本次只修改苹果原生外壳的资源生命周期，不修改绿云、阿里服务器、视觉助手四个模块和导航规则。
- 本地桥接测试 23/23、启动生命周期测试 9/9 通过；真机安装包需完成云端编译后再验收。

## 当前范围

这是独立于现有网页生产环境的 iPhone 原生工程。App 首页直接加载绿云现有完整网页，保持已经验证的界面、任务分发、合同和三个功能不变；原生层只补充苹果硬件能力。当前验证：

- 与绿云网页版相同的完整界面；
- 网页现有的后置摄像头和麦克风链路；
- 闪光灯人工开关，默认关闭，不允许模型自动控制；
- 支持机型上的 ARKit LiDAR 同步深度；
- 苹果原生 ARKit 独占后置主摄，网页通过应用内视频流继续使用同一画面，避免网页相机和原生相机互相抢占；
- 原生画面固定为竖屏后置主摄、中央 9:16 视野，找东西和持续播报使用与深度同步的同一帧；
- 到绿云 Gemini 服务的 HTTPS 连接；
- 为主动提醒、找东西、持续播报和后续导航现场辅助预留互斥任务状态。

当前没有修改阿里和绿云线上代码，也没有修改导航规则。

应用顶部提供两个互斥入口：“绿云 Gemini 版”和“阿里百炼版”。两个入口共用 Apple 原生相机、LiDAR 距离和闪光灯底座；切换入口会销毁旧网页会话，防止两个任务同时运行。两者的主要对比变量是线上图片快筛模型，服务器内原有模块规则保持不变。

内部可执行文件和应用包使用 ASCII 名称 `AccessibleVision`，避免 Windows 七天签名工具无法处理中文路径；手机桌面和旁白显示名仍为“实时慧眼”。

## 架构边界

- 绿云网页仍负责 Gemini Live、合同签发、图片快筛、语音链路和已经验证的任务界面。
- 原生客户端外壳负责安装、系统权限、闪光灯和后续 LiDAR；不得擅自改变网页模块逻辑。
- LiDAR 只负责找东西的走近或伸手阶段，以及持续播报明确要求距离时的距离素材；不改目标、不改左右、不改任务类别、不补合同。
- 找东西只有在模型确认目标可见、没有手入镜并给出目标坐标后，才允许 LiDAR 在“继续走近”和“可以伸手”之间机械裁决。手部方向、接触和完成仍由原找东西模块负责。
- LiDAR 暂时以 0.85 米作为进入伸手阶段的初始真机校准值，超过 1.10 米解除近距离锁定。该数值只属于苹果体验版，必须根据真机桌面和地面样例再校准。
- 持续播报没有明确距离意图时不使用 LiDAR；明确要求距离时直接使用苹果同步深度，不再等待绿云单目测距。LiDAR 不可用时自动回退原绿云链路。
- 导航以后只向现场辅助提供当前路段、下一步动作、终点道路和待确认目标；原生视觉层不得重新规划路线。

## 在 Mac 上生成工程

需要 macOS、Xcode 和 XcodeGen。进入本目录后运行：

```sh
xcodegen generate
open AccessibleVision.xcodeproj
```

在 Xcode 的 Signing & Capabilities 中选择自己的 Personal Team，再用数据线连接 iPhone 运行。免费 Apple ID 的设备签名通常七天后失效，需要重新运行安装。

## 第一轮真机验证

1. 启动后允许摄像头权限。
2. 点“打开闪光灯”，确认灯亮；再点一次确认关闭。
3. 进入找东西，分别在远、中、近三档确认先走近、后伸手，目标、左右和接触逻辑保持原样。
4. 用桌面目标和地面目标各做一轮；走近、蹲下或调整俯角后都重新以同一时刻的目标坐标和深度裁决。
5. 进入持续播报，普通任务不得播报距离；明确要求距离时应使用苹果 LiDAR，并且不等待绿云单目测距。
6. 使用不带 LiDAR 的设备时必须回退原绿云测距或普通视觉流程，不能伪造雷达距离。

三个现场样例将在硬件底座通过后接入：桌面充电宝、倒水快满提醒、房间持续播报。
